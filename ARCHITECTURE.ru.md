# Как устроена Resona

[English](ARCHITECTURE.md) · Русский

Короткая карта кода, чтобы было понятно, куда смотреть. Это не полный справочник, а ровно столько, чтобы сориентироваться и не наступить на странные места.

## Общая картина

```
app/          приложение для Android (Kotlin, Jetpack Compose)
ios/          порт на iOS (Kotlin Multiplatform + Compose Multiplatform)
docs/         сайт на GitHub Pages
fastlane/     описание приложения и скриншоты в формате fastlane
.github/      canary CI
```

Android и iOS это **две отдельные кодовые базы**. Порт на iOS начинался как копия кода Android и теперь живет своей жизнью: в него приходят фиксы, когда SoundCloud что-то ломает, но новые фичи обычно сначала появляются на Android. Так что если вы чините баг, связанный с SoundCloud, он скорее всего есть в обоих местах.

## Приложение для Android

Всё лежит в `app/src/main/java/com/savoo/scclient/`. Стек обычный для Android: Compose для интерфейса, Hilt для DI, Room для базы данных, Retrofit + OkHttp для сети, Media3 для воспроизведения.

Данные идут привычным путем:

```
экран (Compose)  ->  ViewModel  ->  репозиторий  ->  API SoundCloud / Room / DataStore
```

### Работа с SoundCloud

У SoundCloud нет публичного API для таких приложений, поэтому Resona использует тот же `api-v2`, что и сайт. Это самая хрупкая часть приложения, и время от времени она ломается.

**client_id.** Он нужен в каждом запросе. `ClientIdProvider` достает его из JavaScript-бандлов soundcloud.com и кеширует. Когда SoundCloud его меняет, приложение получает новый (не чаще раза в 5 минут, чтобы не долбить сайт).

**Три вида HTTP-клиентов** (смотрите `di/NetworkModule.kt`):

- основной для `api-v2`, с `AuthInterceptor`, который добавляет client_id и токен и ловит капчи DataDome
- обычный для LRCLIB, Genius, релизов GitHub и всего, что не SoundCloud
- `WebViewApiBridge`, скрытый WebView, который делает `fetch()` для лайков, комментариев и редактирования профиля

WebView здесь не ради забавы. SoundCloud защищает эти эндпоинты через DataDome, а DataDome смотрит на TLS-отпечаток соединения. OkHttp совсем не похож на браузер, а WebView похож. Одни куки не помогают.

**Капча DataDome.** Когда она появляется, `DataDomeChallenge` открывает шторку, пользователь ее проходит, и запрос повторяется.

**С массовыми действиями не торопитесь.** Если быстро лайкнуть сотни треков, аккаунт получит предупреждение о спаме на 24 часа (`429 spam_warning`) и капчу. Всё, что много пишет в SoundCloud, должно делать паузы.

### Как играет трек

1. У трека есть список `transcodings`, это разные форматы стрима.
2. `UnavailableTrack.kt` решает, можно ли его воспроизвести. **Если хотя бы один transcoding зашифрован, трек не играет.** Обычные mp3 рядом с ним выглядят нормально, но всегда отдают 404, не ведитесь. Resona не расшифровывает DRM и не будет.
3. `TrackRepository.resolvePlayableStream()` сначала пробует progressive mp3, потом HLS.
4. `PlayerController` и `PlaybackService` (Media3) уже играют его, ведут очередь и уведомление.

Офлайн-загрузки идут через `OfflineTrackManager`, по одному треку за раз, с теми же правилами про DRM.

### Тексты песен

`LyricsRepository` перебирает источники по порядку:

1. локальный кеш в Room
2. LRCLIB (синхронизированный текст, при ошибке запрос повторяется несколько раз)
3. Genius как запасной вариант (просто текст, без таймингов)

Если версия песни на SoundCloud длиннее или короче, чем на LRCLIB (ускоренная версия, ремикс), тайминги автоматически растягиваются по соотношению длительностей. Еще пользователь может сам подстроить сдвиг и растяжение для каждого трека. Если текст разъезжается, почти всегда дело в этом, а не в плеере.

Аннотации Genius берутся из его API `referents`. Genius отвечает 403, если запрос не похож на запрос из мобильного браузера, поэтому его клиент отправляет браузерный User-Agent.

### Хранение данных

- **Room** (`AppDatabase`): избранное, плейлисты, офлайн-треки, история прослушиваний, кеш текстов, импорт из Telegram и не только. У каждой версии есть миграция и JSON схемы в `app/schemas/`, миграции проверяет `AppDatabaseMigrationTest`.
- **DataStore** (`SettingsRepository`): все настройки.
- **Зашифрованные настройки** (`SecurePrefs`): токены и другие секреты.

### Сборки

| Сборка | App id | Зачем |
|---|---|---|
| debug | `com.savoo.scclient.debug` | разработка |
| canary | `com.savoo.scclient.canary` | собирается в CI на каждый пуш в `main` |
| release | `com.savoo.scclient` | релизы на GitHub |

Все три ставятся рядом друг с другом. APK разделены по ABI, потому что нативные библиотеки TDLib большие.

CI (`.github/workflows/canary.yml`) гоняет юнит-тесты, собирает canary APK и неподписанный IPA и публикует их вместе как пре-релиз `canary`.

## iOS

```
ios/shared/src/commonMain/   большая часть кода, те же папки, что на Android
ios/shared/src/iosMain/      то, что специфично для iOS
ios/iosApp/                  маленькая точка входа на Swift
```

Порт вышел дешевым благодаря `compat/`: это небольшие заменители API Android (OkHttp, Media3, SharedPreferences, WebView, Context и прочие), написанные поверх мультиплатформенных библиотек. За счет них большая часть кода с Android переехала почти без изменений.

В `iosMain` то, что на iOS правда устроено иначе: аудиоплеер на AVFoundation, звуковые эффекты, биометрия, вибрация, выбор файлов.

IPA не подписан, пользователи ставят его через сайдлоад. Смотрите [инструкцию по установке](https://savo-o.github.io/resona/ios.html).

## Переводы

Английские строки лежат в `app/src/main/res/values/strings.xml`, русские в `values-ru`. Переводы от сообщества ведутся в отдельном репозитории [resona-status](https://savo-o.github.io/resona-status/translations/), который сам подтягивает шаблон из последнего релиза. Пользователи загружают их в приложении через «Свой» язык, в сборку ничего не вшивается.

## Когда что-то сломалось

Чаще всего виноват SoundCloud, а не приложение. С чего начать:

- вообще ничего не грузится: client_id (`ClientIdProvider`), попробуйте принудительно обновить его в настройках
- не работают лайки или комментарии: DataDome (`WebViewApiBridge`, `DataDomeChallenge`)
- трек не играет: transcodings (`UnavailableTrack.kt`, `TrackRepository`)
- текст разъезжается: длительность не совпадает с LRCLIB (`LyricsRepository`)

В меню отладки в debug и canary-сборках есть логи и пара инструментов, которые тут помогают.
